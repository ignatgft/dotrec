# AGENTS.md — инструкции для агента

Ты строишь Android-приложение **DotRec** (запись экрана). Этот файл главный. При конфликте с другими документами приоритет такой: `AGENTS.md` → `docs/02-requirements.md` → остальное.

## Принципы

1. **Скорость запуска записи важнее количества функций.** От тапа до первого кадра не более 1 секунды (без учёта системного диалога согласия).
2. **Минимализм.** Если функции нет в `docs/02-requirements.md`, её не добавляй. Идеи из `docs/11-features-catalog.md` разрешено делать только после переноса в требования с ID (шаблон в конце каталога). Новые идеи складывай в `docs/10-risks-open-questions.md`.
3. **Вся запись в Kotlin.** Flutter только рисует интерфейс и шлёт команды. Видео никогда не проходит через Dart.
4. **Две темы с первого дня.** Любой экран проверяется в светлой и тёмной теме.
5. **Честность вместо магии.** Если функция недоступна на устройстве (например, 90 FPS на экране 60 Гц), UI показывает это, а не молчит.

## Порядок работы

1. Возьми следующую незакрытую задачу из `docs/08-roadmap-tasks.md`.
2. Прочитай связанные разделы требований (ID вида `FR-REC-01`).
3. Реализуй. Пиши минимум кода, который закрывает критерии приёмки.
4. Запусти проверки (см. ниже).
5. Отметь задачу `[x]`, сделай коммит `T-XX: краткое описание`.
6. Если задача заблокирована или требования неоднозначны, остановись, запиши вопрос в `docs/10-risks-open-questions.md` и переходи к следующей независимой задаче.

## Технические правила

**Flutter / Dart**
- Dart 3.x, Flutter stable. Null safety, `flutter_lints` + строгий `analysis_options.yaml`.
- Состояние: `flutter_riverpod` (`Notifier`/`AsyncNotifier`). Без `setState` для бизнес-логики.
- Каналы платформы только через слой `platform/` (см. `docs/05-flutter-app.md`). Виджеты не вызывают `MethodChannel` напрямую.
- Все цвета, радиусы и отступы берутся из темы (`DotTheme`). Хардкод цветов в виджетах запрещён.
- Все строки в `l10n` (ARB). Языки: `ru`, `en`.
- Шрифт точечный (Doto, лицензия OFL) лежит в `assets/fonts/`, а не грузится из сети.

**Kotlin / Android**
- `minSdk 29`, `targetSdk 35`, `compileSdk 35`. Kotlin 2.x, корутины.
- Запись живёт в `ForegroundService` с типом `mediaProjection`. Состояние хранится в сервисе, а не в Activity.
- Один источник правды о состоянии записи: `RecorderStateStore` (StateFlow). Плитка, виджет, уведомление и Flutter подписаны на него.
- Не использовать устаревшие API без причины. Для каждого обхода по версии Android оставь комментарий с номером API.
- Нет сторонних зависимостей в нативном слое, кроме `kotlinx-coroutines` и `androidx.*`.

## Что нельзя

- Передавать видеопоток через Dart или MethodChannel.
- Добавлять аналитику, рекламу, водяные знаки, сетевые запросы. Приложение полностью офлайн, разрешения `INTERNET` в манифесте нет.
- Запрашивать разрешения заранее. Только в момент, когда они нужны (микрофон при включении микрофона и т. д.).
- Придумывать API Android по памяти. Если не уверен, прочитай документацию или оставь `TODO(verify)` и вопрос в `docs/10`.
- Менять публичный контракт каналов (`reference/channel_contract.md`) без обновления документа и обеих сторон.
