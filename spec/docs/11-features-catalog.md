# 11. Каталог возможностей (backlog и расширения)

Это **не** обязательные требования. Базовый набор v1 описан в `02-requirements.md`.
Здесь собраны идеи расширений с оценкой пользы, сложности и рисков, чтобы их можно было брать по очереди.

**Правило продвижения (для агента):** возможность из каталога разрешено реализовывать только после того, как её перенесли в `02-requirements.md` с ID и приоритетом, а в `08-roadmap-tasks.md` появилась задача. Сам по себе каталог разрешением на разработку не является.

Оценки: польза (★1–3), сложность (S/M/L), риск (низкий/средний/высокий).

## A. Захват

| ID | Возможность | Польза | Сложн. | Риск | Заметки |
|---|---|---|---|---|---|

## Рекомендуемый порядок продвижения

**Волна 1 (дёшево и сильно):** FX-CTL-05, FX-QLT-04, FX-QLT-02, FX-CAP-01, FX-REL-03, FX-PRV-01, FX-UI-03, FX-UI-01.
**Волна 2:** FX-POST-01, FX-REL-01, FX-CTL-01, FX-LIVE-03, FX-CAP-05, FX-UI-07, FX-POST-05.
**Волна 3 (после M4, требует MediaCodec-пайплайна):** FX-CAP-03, FX-AUD-01, FX-AUD-02, FX-POST-03, FX-QLT-01.
**Отложить или отклонить:** FX-QLT-05, FX-QLT-06, FX-LIVE-05, FX-CAP-02 (дорого или хрупко).

## Флаги возможностей
Каждая возможность из каталога при реализации включается через локальный флаг (`FeatureFlags` в `core/`), по умолчанию выключена для экспериментальных (FX-LIVE-02, FX-CAP-03, FX-QLT-05) и включена для проверенных. Флаги не ходят в сеть.
